Sentinel User Manual

Welcome to the User Manual for Sentinel — a deterministic reliability harness for AI coding agents. This document covers everything from basic concepts to integrating Sentinel into your own AI workflows.

1. Traditional Workflow vs Sentinel Workflow

WITHOUT Sentinel (Traditional)

Developer gives task to AI agent (Cursor, Copilot, Aider, etc.)
Agent generates code changes
Agent says 'Done! I fixed the bug'
Developer manually reviews the diff
Developer manually runs tests
Developer discovers agent hallucinated / code is broken
Developer manually reverts changes
Developer re-prompts the agent
Repeat until it works (or give up)
Pain points: No safety guardrails, no automatic verification, blind trust in LLM output, manual recovery, wasted time

WITH Sentinel

Developer gives task to Sentinel
Sentinel creates isolated git worktree (base repo stays immutable)
Sentinel's orchestrator asks LLM to generate a plan
For each step: LLM proposes tool call → Sandbox validates (path jail + command whitelist + credential stripping) → Tool executes in isolation
After all steps: Verifier independently runs pytest + checks git diff
If tests fail: RecoveryController rolls back workspace via git, injects diagnostics, retries automatically (up to 3x)
If tests pass + diff is valid → DONE ✓ with deterministic proof
Benefits: Zero trust in LLM self-reports, sandboxed execution, automatic recovery, reproducible benchmarks

2. Prerequisites

  • Python 3.10+ (tested on 3.14)
  • Git (for worktree isolation and diff analysis)
  • Optional: Docker (for full container-level sandboxing; falls back to host subprocess with weaker isolation on Windows)
  • Optional: Ollama (for local LLM inference) or a Groq API key (for cloud inference)

3. Installation & Setup

# Clone the repository
git clone <repo-url>
cd iqoo

# No pip install needed for core! Zero external dependencies.
# The entire backend uses Python stdlib only (urllib, subprocess, json, dataclasses)

# For the API server (optional, for dashboard):
pip install fastapi uvicorn

# Start the API server:
python -m uvicorn sentinel.server.api:app --reload --port 8000

4. Quick Start — Running Your First Task

Run the CLI demo to see Sentinel in action interactively:

python -m sentinel.cli.demo

To see a side-by-side benchmark comparison between a raw agent and a Sentinel-wrapped agent:

python -c "from sentinel.benchmark.runner import run_comparative_benchmark; run_comparative_benchmark()"
Benchmark Output Explained

The raw agent often fails by making false claims about fixing a bug without actually testing it. The Sentinel-wrapped agent, however, verifies the results independently and either succeeds with deterministic proof or fails safely.

5. Configuring Models

Sentinel provides three model adapter options out-of-the-box:

MockModelAdapter (Default for benchmarks)

  • Uses scripted responses for deterministic testing
  • No external service needed

OllamaAdapter (Local inference)

# Install Ollama: https://ollama.ai
ollama pull llama3.1:8b
# Sentinel connects to http://localhost:11434/api/generate

GroqAdapter (Cloud inference)

export GROQ_API_KEY="gsk_..."
# Sentinel connects via urllib to https://api.groq.com/openai/v1/chat/completions
# Recommended model: llama-3.1-8b-instant

You can easily switch between them using the factory function:

from sentinel.agent.model_adapter import get_model_adapter

adapter = get_model_adapter("ollama")   # local
adapter = get_model_adapter("groq")     # cloud
adapter = get_model_adapter("mock")     # testing

6. Integrating Sentinel With Your Own Agent / Codebase

Follow these steps to integrate Sentinel into your projects:

  1. Prepare your repo: Your codebase needs a test suite (pytest, unittest, etc.) — Sentinel uses real test execution as its ground truth.
  2. Create a TaskState: 
    from sentinel.core.types import TaskState

state = TaskState(
    task_id="my-bugfix-001",
    workspace_path="/path/to/git/worktree",
    instruction="Fix the authentication timeout bug in auth.py",
    status="planning",
)
  3. Choose your model adapter and run: 
    from sentinel.agent.orchestrator import run_task_loop
from sentinel.agent.model_adapter import get_model_adapter

adapter = get_model_adapter("ollama")  # or "groq"
final_state = run_task_loop(
    state=state,
    test_command="pytest tests/",
    model_adapter=adapter,
    expected_files=["auth.py"],  # boundary — only these files should be modified
    max_attempts=3,
)

print(f"Result: {final_state.status}")  # "done" or "failed"
print(f"Verified: {final_state.verifier_result}")
  4. Use workspace isolation (recommended for production): 
    from sentinel.sandbox.workspace import create_task_workspace, destroy_task_workspace

ws_path = create_task_workspace(
    repo_path="/path/to/your/repo",
    base_commit="HEAD",
    task_id="my-bugfix-001",
)
# Agent works in ws_path — your original repo is NEVER touched
# When done:
destroy_task_workspace("my-bugfix-001")
  5. Add chaos testing (optional but recommended): 
    from sentinel.chaos.injector import FailureInjector
from sentinel.chaos.faults import FaultClass

injector = FailureInjector(seed=42)
state.injected_fault = FaultClass.TRUNCATED_DIFF.value

# Now run_task_loop will inject the fault and test recovery
